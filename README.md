## Introduction

Surface Evolver (SE) solves foam, capillary-surface, minimal-surface and wetting problems by representing a soap film as an explicit triangulated surface with arbitrary topology, then minimizing area subject to volume, contact-angle, periodicity and anisotropy constraints. That *mathematical formulation* remains the right fit for these problems; what has aged is the *numerical implementation*: hand-written gradients and Hessians, direct factorization of the exact Hessian, heuristic topology surgery, and no automatic differentiation, algebraic multigrid or GPU support.

This project keeps the formulation and replaces the numerics, as an independent Python prototype:

| Area | Surface Evolver | This prototype |
|---|---|---|
| Derivatives | Hand-coded gradient/Hessian | `torch.autograd` — `grad` and Hessian-vector products, no assembled Hessian |
| Minimizer | Gradient descent + exact Hessian | L-BFGS (default) and trust-region Newton-CG (high accuracy) |
| Volume constraint | Lagrange multiplier / projection | Augmented Lagrangian, with radial projection as fallback |
| Contact angle | Wall facet bookkeeping | Line-integral wetting energy with an analytic gradient |
| Topology changes | Heuristic `refine`/`swap`/`collapse`/`pop` | Same operations with preconditions and post-operation invariants |
| Diffuse alternative | — | Allen-Cahn phase field (topology events without mesh surgery) |
| Smooth 1-D problems | — | RBF-FD mesh-free solver |

The prototype does **not** modify SE's C source, build a GUI, or claim production-grade performance. Surface Evolver is used strictly as a baseline: it runs in a scratch directory, and its datafiles and dumps are parsed read-only.

## Benchmark Results

Every replacement is measured against SE or against a closed-form solution. All numbers below are produced by the committed scripts and recorded in [`se-modern/reports/REPORT.md`](se-modern/reports/REPORT.md) and [`se-modern/reports/results.json`](se-modern/reports/results.json).

| Branch | What is replaced | Gate | Measured result |
|---|---|---|---|
| Phase 0 | Mesh, `.fe`/`.dmp` I/O, energy | Area/volume vs SE within `1e-10` | Relative error **2e-16** |
| B1 | Optimizers | `‖g‖∞ < 1e-6`, area vs SE `< 1e-6` | Area matches SE to **1.96e-16**; TR-CG converges in 3 iterations vs L-BFGS 12 |
| B2 | Volume / contact angle / periodicity / anisotropy | Volume `< 1e-8`, angle `< 0.5°` | Volume error **4e-15**; contact angle within **0.245°** |
| B3 | Topology surgery | 0 invariant failures over 100 random operations | **0 failures** |
| B4 | Phase field (Allen-Cahn) | Radius error `< 5%`, merge to 1 component | **1.19%** at N=32, **0.10%** at N=48; 2 → 1 components |
| B5 | Mesh-free RBF-FD | Profile error `< 1%`, residual `< 1e-6` | **1.22e-4** profile error, **8.8e-11** residual |

The study's conclusions — which parts of SE to keep, replace, or mix — are summarized in the [report's recommendation section](se-modern/reports/REPORT.md). In short: keep the explicit-surface formulation (accuracy, controllable topology, direct comparability with SE), replace the numerical kernel, and use the phase-field model for topology-dominated stages and the mesh-free solver for smooth axisymmetric subproblems.

Numerics run in `torch.float64` on CPU by default.

SE is located in this order, and the first hit wins: `evolver64` on `PATH`, then `evolver` on `PATH`, then `E:\Mybat\evolver64.exe`, then `E:\Mybat\evolver.exe`. To override, put the binary on `PATH`. When no binary is found, tests and benchmarks that need SE are skipped via `pytest.mark.skipif` rather than failing — everything else still runs.

## Installation

There is no packaging manifest, so the project is used in place. Clone, then make `src/` importable:

```bash
git clone <repository-url> evolver_alternative
cd evolver_alternative
```

Install the Python dependencies (the versions above are what the gates were verified with):

```bash
python -m pip install torch numpy scipy scikit-image pytest
```

Every command in this README runs from `se-modern/` with `src/` on the import path:

```bash
cd se-modern
export PYTHONPATH=src          # Windows cmd: set PYTHONPATH=src
```

Optional, for the SE baselines: place `evolver64`/`evolver` on `PATH`, or install to `E:\Mybat\` (the default fallback location).

The six SE benchmark datafiles (`cube`, `cat`, `sphere`, `mound`, `phelanc`, `octa`) are already vendored in `se-modern/data/se/`, so cloning the repository is enough to run every gate.

## Usage

### Command line

The CLI runs one benchmark case at a time and exits with that case's pass/fail status.

```bash
# List the available cases
python -m semodern.cli list

# Run a single case (cube is the merge gate shared by every branch)
python -m semodern.cli run --case cube

# Other cases: catenoid, cube_sphere, sessile, periodic, aniso, octa, phasefield, meshfree
python -m semodern.cli run --case catenoid
```

### Optimizers

Both minimizers accept any object exposing `value(x)`, `grad(x)` and `hvp(x, v)` — the `semodern.energy.Energy` interface — with a flat float64 starting vector of shape `(3n,)`.

Area alone has no lower bound, so an unconstrained run on a closed mesh collapses it to zero energy. The example below minimizes area plus a fixed-penalty volume term, which is well posed and is what the two solvers are compared on.

```python
import sys
sys.path.insert(0, "src")

from semodern import constraints, energy, io_fe, optimize

mesh = io_fe.load_fe("data/se/cube.fe")
base = energy.Energy(mesh.faces)
volume = constraints.VolumeConstraint(mesh.faces, volume0=1.0)
problem = constraints.AugmentedEnergy(base, volume, lam=0.0, rho=10.0)

for name, solver in (("lbfgs", optimize.lbfgs), ("tr_newton_cg", optimize.tr_newton_cg)):
    result = solver(problem, mesh.verts.reshape(-1), max_iter=200, tol=1e-8)
    print(name, result.energy, result.grad_norm, result.iterations, result.converged)
```

Output on the vendored `cube.fe` — both solvers reach the same energy, and Newton-CG needs far fewer iterations because it uses curvature through `hvp`:

```text
lbfgs: energy=4.436810 gn=3.316e-09 iters=32 conv=True vol=0.594701337
tr_newton_cg: energy=4.436810 gn=1.360e-11 iters=6 conv=True vol=0.594701334
```

### Volume-constrained minimization

The augmented Lagrangian *holds* `V(x) = V0`: each outer iteration minimizes the augmented objective, then updates the multiplier and penalty. Use this instead of the fixed-penalty form above when the volume must be satisfied rather than merely discouraged.

```python
import sys
sys.path.insert(0, "src")

from semodern import constraints, energy, io_fe

mesh = io_fe.load_fe("data/se/cube.fe")
base = energy.Energy(mesh.faces)
volume = constraints.VolumeConstraint(mesh.faces, volume0=1.0)

outcome = constraints.augmented_lagrangian(
    base, volume, mesh.verts.reshape(-1), outer=8, inner_iter=200
)
print(outcome["volume"], outcome["relative_residual"], outcome["converged"])
```

This prints a volume of `1.000000000181` with a relative residual of `1.8e-10` and `converged=True`.

### Topology operations

Each operation validates its preconditions *before* changing anything and the full mesh invariants *after*, so it either returns a valid mesh or raises `ValueError` with the input untouched.

```python
import sys
sys.path.insert(0, "src")

from semodern import mesh as mesh_mod, topology

refined, change = topology.refine(topology.tetrahedral_fixture())
print(change.before, "->", change.after, "delta", change.delta)
print("Euler characteristic:", mesh_mod.euler_characteristic(refined))
```

## Build & Test

There is no compilation step. Run the test suite from `se-modern/`:

```bash
export PYTHONPATH=src          # Windows cmd: set PYTHONPATH=src

# Full suite (129 tests)
python -m pytest -q

# One area only
python -m pytest -q tests/test_optimize.py
python -m pytest -q tests/test_phasefield.py
```

The `cube.fe` smoke test is the merge gate shared by every branch: it dumps the initial mesh, checks 14 vertices and 24 faces, compares Python area/volume with SE's reported values, evolves two SE steps, and asserts the area did not increase. It exits non-zero and prints `SMOKE FAIL: <reason>` on any violation.

```bash
python benchmarks/smoke_cube.py    # prints "SMOKE PASS"
```

The full benchmark sweep runs each branch's script, merges every `reports/results.*.json` into `reports/results.json`, and exits non-zero if any gate failed:

```bash
python benchmarks/run_all.py

# Subset selection
python benchmarks/run_all.py --only b1
python benchmarks/run_all.py --skip b4,b5
```

Regenerate the report after a sweep:

```bash
python benchmarks/make_report.py   # writes reports/REPORT.md
```

## Contributing

1. Branch from `main` using `feat/<area>` (for example `feat/b2-constraints`).
2. Make a surgical change: keep the public signatures documented above stable, since later stages depend on them (`Energy.value/grad/hvp`, `lbfgs`/`tr_newton_cg`, `OptResult`).
3. Before merging, all of the following must pass:
   ```bash
   python -m pytest -q
   python benchmarks/smoke_cube.py
   python benchmarks/<your-area>.py
   git status --short      # must show only your own files
   ```
4. Merge with `git merge --no-ff <branch>` so branch history is preserved.
5. If a numerical change alters a gate result, update `reports/results.<branch>.json` and re-run `benchmarks/make_report.py` — the report is generated from measurements, never hand-edited.

Code follows these conventions: identifiers, strings, log and error messages in English; comments explain intent and invariants, not mechanics.
